# 2. Card

Compound surface with header + content + footer sub-components. Standard form uses `rounded-xl`; dense list forms override to `rounded-lg`. Pair with `border` (hairline) + `shadow` — never `shadow-md` or `shadow-lg`.

<Demo heading="Card — standard form">
  <div className="w-80">
    <Card>
      <CardHeader>
        <CardTitle>账号组</CardTitle>
        <CardDescription>今日新增 2 个账号</CardDescription>
      </CardHeader>
      <CardContent>
        <p className="text-sm">这里放卡片正文内容，通常是一段短语或一组数据。</p>
      </CardContent>
    </Card>
  </div>
</Demo>

<Demo heading="Card — with footer">
  <div className="w-80">

        <Button variant="outline">取消</Button>
        <Button variant="destructive">确认删除</Button>
      </CardFooter>
    </Card>
  </div>

# 3. Input

Single-line text input. Focus state shows amber halo at `focus-visible:ring`. Pair with a visible `<Label>` for accessibility — placeholder alone is NOT sufficient labelling.

<Demo heading="Input — states">
  <div className="grid w-72 gap-3">
    <Input placeholder="账号名称" />
    <Input placeholder="禁用" disabled />
    <Input placeholder="aria-invalid 状态" aria-invalid />
  </div>
</Demo>

<Demo heading="Input — paired with label" caption="Label + htmlFor OR aria-label; placeholder alone fails a11y tests.">
  <div className="grid w-72 gap-2">
    <label className="text-xs font-medium text-muted-foreground" htmlFor="demo-input">账号名称</label>
    <Input id="demo-input" placeholder="留空将使用默认值" />
  </div>
</Demo>

# 4. Popover

Anchored transient UI for pickers / filters / config. `Esc` + outside-click both close. Focus returns to trigger on close. `asChild` on the trigger for clean Radix Slot semantics.

<Demo heading="Popover — anchored picker">
  <Popover>
    <PopoverTrigger asChild>
      <Button variant="ghost">选择账号组</Button>
    </PopoverTrigger>
    <PopoverContent>
      <div className="space-y-2">
        <p className="text-sm font-medium">账号组</p>
        <p className="text-xs text-muted-foreground">这里放选择列表，popover 内容由调用方决定。</p>
      </div>
    </PopoverContent>
  </Popover>
</Demo>

# 5. Dialog

Modal blocking dialog. `<DialogTitle>` is REQUIRED for screen-reader announcement — without it, SR cannot announce purpose on open. Overlay is `bg-black/80` per system contract; do NOT lift modal backdrop to a non-dimmed overlay.

<Demo heading="Dialog — destructive confirm">
  <Dialog>
    <DialogTrigger asChild>
      <Button variant="destructive">删除账号组</Button>
    </DialogTrigger>
    <DialogContent>
      <DialogHeader>
        <DialogTitle>确认删除</DialogTitle>
        <DialogDescription>该账号组下的 3 个账号将被解绑，且无法撤销。</DialogDescription>
      </DialogHeader>
      <DialogFooter>
        <Button variant="outline">取消</Button>
        <Button variant="destructive">确认删除</Button>

# 6. SidebarRow

Pattern lives inline in `src/App.tsx` — NOT a separate component file. Active row uses **ink + 2px primary strip**, NO row-level fill. Inactive rows use muted text + hover-only `bg-foreground/[0.04]` tint (subtle hover, NEVER steady-state).

# 7. StatusBadge

# 8. ProgressBar

Determinate linear progress. Fill animates via `transform: translateX()` (NOT via `width` mutations, to avoid layout thrash). Pair with a mono numeric label so SR users hear both the percentage and the context.

# 9. Toast

Five types via `useToast()` — 4-band semantic (success / warning / info / error) + `default`. Auto-dismiss after 3s with a 300ms exit animation. Must run inside `<ToastProvider>` (CatalogPage wraps the whole page).
